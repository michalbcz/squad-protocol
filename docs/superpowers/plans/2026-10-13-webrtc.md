# WebRTC implementation plan

> Use superpowers:executing-plans inline; verification-before-completion governs delivery.

**Goal:** Two friends play from the static branch preview via WebRTC.
**Architecture:** Shared Rooms authority, host loopback, remote reliable data channel, existing NetSession.
**Tech Stack:** TypeScript, Web Crypto, RTCPeerConnection/RTCDataChannel, Svelte 5, zod, Vitest/Playwright.
**Spec:** docs/superpowers/specs/2026-10-13-webrtc-design.md

## Constraints and review focus

- Preserve engine purity, filtered views/events and bounded authority.
- New signaling format v1, bounded code/frame sizes, explicit timeout/invalid-code behavior.
- No default WebSocket requests on static hosting; existing Node invite/resume stays available.
- Code/relay credentials in memory only; both RTC tabs must stay open.
- Validate wrong-role answer, failed gathering, disposal during setup, repeated connect clicks, and temporary/terminal disconnects.
